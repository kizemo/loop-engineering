# 博文写作 SOP · Loop Engineering 复用项目

> 从已发布的 2 篇博文沉淀:固定格式、双交付纪律、信源核实到官方、章节结构约束。
> 本 SOP 是所有 loop engineering 相关博文(包括 Playbook 实战报告、LoopX 跟进报道)的写作标准。

---

## 一、固定 frontmatter(必填)

每篇博文开头必须包含以下 4 个块,顺序固定:

```markdown
# <标题>

> 80 字摘要:<一句话讲清楚这篇博文要解决什么问题 + 关键论点 + 适用读者>

**关键词**:<10 个,逗号分隔>
```

### 1.1 标题要求

- 中文标题为主,英文 3.5k⭐ 类英文点缀可保留
- 长度建议 ≤ 30 字
- 必含核心关键词(LoopX / cc-haha / Hooks 等)

### 1.2 80 字摘要要求

- **严格 ≤ 80 字**(包括标点)
- 必须包含 3 个要素:**问题 + 论点 + 读者**
- 例:`LoopX(GitHub 3.3k⭐、MIT 协议、Python 3.11+ 实现、零运行时依赖)是一个 "agent 中立" 的本地控制平面。它用目标、待办、人工门禁、证据、配额五大原语, 把 Claude Code、Codex、OpenCode、Pi、Cursor 这些 AI Agent 串成可暂停、可交接、可审计的长时运行工作流, 并保留人类对危险操作的最终裁决权。`

### 1.3 关键词要求

- **恰好 10 个**(允许 9-11 个浮动)
- 全部中文逗号分隔
- 前 3 个必含"loop engineering / Claude Code / cc-haha / LoopX"中的至少 1 个
- 例:`LoopX、长时运行 Agent、控制平面、本地优先、人工门禁、Agent 中立、Claude Code 适配、Loop 工程、证据追踪、配额管理`

## 二、章节结构约束

| 层级 | 数量 | 作用 |
|---|---|---|
| **一级 `#`** | 1 个 | 主标题(写在 frontmatter 之后) |
| **二级 `##`** | ≤ 10 个 | 主要章节,中文数字编号(一、二、三...)或英文 |
| **三级 `###`** | ≤ 20 个 | 子章节,数字编号(3.1、3.2...) |
| **四级 `####`** | 极少使用 | 仅用于"方法 A/B/C/D"这种并列分项 |

### 2.1 二级章节推荐顺序

1. 引子/问题陈述(1-2 段引用 Karpathy/官方原话)
2. 核心概念解释
3. 实操(分步 + 代码块)
4. 对照表(其他方案 vs 本方案)
5. 误区 / 反模式
6. 入门清单 / Quickstart
7. 哲学/方法论收尾
8. 参考资料

### 2.2 三级章节编号

二级章节内的三级统一用 `### 3.1` / `### 3.2` 这种数字编号,不混用中文。

## 三、视觉元素使用频率

| 元素 | 推荐频率 | 用途 |
|---|---|---|
| 引用块 `>` | **频繁**(每段开头或每节引言) | 引官方原话 / Karpathy 原话 / 类比 |
| 代码块 ` ``` ` | **高**(每节 1-2 个) | bash 命令、settings.json、prompt 模板 |
| 表格 `\|---\|` | **频繁**(每节 1-2 个对照) | 原语表、对比表、平台支持表 |
| ASCII 架构图 | **中**(关键流程章节) | PreToolUse 数据流、Sub-agent 调度 |
| 外链(图片/视频) | 极少 | 仅在引官方 demo 视频时 |

## 四、双交付纪律(md + html)

每篇博文**必须**同时交付两个文件:

| 文件 | 用途 |
|---|---|
| `<slug>.md` | 源文件,GitHub / 仓库追踪 |
| `<slug>.html` | 公开网页版本,用 yingdao 紫模板(详见 `HTML-TEMPLATE.md`) |

**命名规范**:
- `<主题>-YYYY-MM-DD.md` 和 `<主题>-YYYY-MM-DD.html`
- 例:`loop-engineering-in-cc-haha-2026-09-25.md` + `.html`

---

## 五、信源核实纪律

每篇博文的引用**必须**附原文出处,包括:

| 信源类型 | 必须标注 |
|---|---|
| Claude Code 官方文档 | 完整 URL,如 `https://code.claude.com/docs/en/hooks` |
| LoopX 仓库 | URL + star 数 + commit 数,如 `loopx-project/loopx, 6k stars, Apache-2.0` |
| Karpathy 原话 | 播客名 + 集数 + 时间,如 `No Priors Podcast · Andrej Karpathy (March 2026)` |
| GitHub 项目 | URL + star + 协议 + 最近 commit |

**禁项**: 不附原文的引用、推测性的"我觉得 LoopX 会..."、未经核实的数据(版本号 / star 数)。

---

## 六、风格约束

- **简体中文为主**,英文术语(`/loop`、Hooks、PreToolUse、Stop、Sub-agents)保留英文
- **结论先行**:每节开头一句话给结论,再展开论证
- **避免堆砌套话**:不写"在当今 AI 飞速发展的时代..."这类开场
- **每节 200-500 字**,过长拆分为 2 节

## 七、博客常用工具

### 7.1 标题技巧

- 数字开头:`7 个 ...`、`5 个 ...`
- 反差:`不是 X,是 Y`
- 反问:`为什么 ... 这么难?`
- 类比:`把 X 当 Y 来看`

### 7.2 一句话定义模板

> **<术语>**:<一个完整的句子,主语+定义+对比结构>

例:**Loop engineering**:把 AI Agent 的"持续运行"当成软件工程问题来解,而不是模型问题。
